# 板块层：D0 启动判定 · 高位闸门 · 全量选股收敛

> 代码：`gates/sector_selfcalc.py`（板块强度 / 高闸门）· `gates/sector_launch.py`（东财+新浪兜底）·
> `screener/sector_dual.py`（收敛层）· `intraday_alert.py`（盘中盯）。
> 真源文件：**`references/sector_map.json`（入仓）**。锚点缓存 `data/sector_high_hist.json`（不入库、可自愈）。

## 一、为什么板块映射要自维护（实测排除的两个源）

2026-10-28 逐个试完，第三方板块接口全都不能用：

| 源 | 结论 |
|---|---|
| 东财 `push2 clist`（概念 516 个，带扩散度+主力净流入，质量最好） | 连续请求后**封 IP**（`RemoteDisconnected` 持续 >10 分钟）；`fs=b:BKxxxx` 成分股参数**一律被拒**；`push2his` 长期 502 ⇒ 拿不到「板块→成分股」，也拿不到板块历史 |
| 新浪行业 `newSinaHy.php`（49 个，3038 只） | **分类质量极差**：`600233 圆通速递 → 服装鞋类`、`300308 中际旭创 → 机械行业`、`600760 中航沈飞 → 汽车制造`；科创板/创业板大量缺失（3002 只覆盖不到 5026）。**不可用** |
| 腾讯 `proxy.finance.qq.com/.../getRank` | 参数名试不出（多种 `sort_type` 全 `code!=0`） |

⇒ 只能自维护。代价是要人工加票，收益是不受任何限流、且**入仓可跨机器/跨 agent 复用**。

## 二、板块 D0（什么时候能进）

三件套，全部即时可算，**首日即可入**，不等 5 日 RS 排名：

```
等权涨幅 ≥ +2.0%   且   超额（vs 创业板指）≥ +1.5pt   且   扩散度（板块内上涨家数比）≥ 70%
```

- 扩散度自己算：板块内上涨家数 / 有效家数，与东财 `f104/(f104+f105)` 同义。
- **实证**：2026-10-19 创业板 −0.94%，机器人传感器 +4.5%、本体 +8.3%、电机 +6.6%、丝杠 +4.4%
  同时判 D0 ⇒ 10-19 就是启动日（当时指数在跌）。传感器 10-16 提前亮，可作前哨。
- 反面标本：麒麟信安 `platform_break` R2.21 图形漂亮，但信创板块在失血 ⇒ −14.05%。
  **禁的是「个股强 + 板块弱」，不禁「板块强 + 个股强」。**

## 三、高位闸门（涨了多少就不能再进）

`gates/sector_selfcalc.py --high`，逐日锚点缓存，盘中只做 `现价/锚点-1`。

| 档 | 触发（任一） | 动作 |
|---|---|---|
| L1 降级 | 距 60 日低点**中位** ≥35% 或 MA20 乖离**中位** ≥12% | 禁追阳线，只准挂回踩 |
| L2 禁开 | 距低点 ≥50% 或 乖离 ≥20% 或 距 D0 ≥30% | 禁新开仓，只持/减 |
| L3 减仓 | 本轮累计 D0 ≥5 次 + 当日等权转跌 + 扩散 <50% | 按个股结构减 |

两条配套规则（缺一条就漏拦）：

1. **弱市加成**：创业板指 < MA10 时，L1 升级为「**连回踩也不接**」。
   老罗原话：「弱市宁愿错过，也不要追高被套，很容易吃到大阴线」。10 月实证：创业板全月 0/15 天站上 MA10。
2. **大类联动** `HIGH_LINK_MIN=1`：同大类（`·` 前）**任一**子板块触发 L1 → 全大类降级。
   机器人本体乖离中位仅 9.6%（均值 16.4% 被个别票拉高）自己不触发，靠电机 39.5% 联动拦下。

⚑ **一律用中位数**：等权均值会被单票打歪（CXO 等权 +75.2% vs 中位 +15.8%，差值是近岸蛋白 +272%）。
⚑ **D0 计数不能用「连续 D0」口径**：机器人 10-16/19/20/23/28 中间夹着回踩日，连续口径把 5 次算成 1 次。
正确做法：往回扫，遇**连续 3 日非 D0** 才断。

## 四、收敛层：screener/sector_dual.py

```
第1层 板块层   本轮 D0 且在窗口内 + 未触高位闸门
第2层 双通过   战法闸 + 筹码闸（scr_<日期>_close.jsonl 的 scr.allow_new）
第3层 飙股     板块内弹性日数分位 ≥75
```

**窗口**（不能只看「本轮第几次 D0」，必须叠当日状态）：

| 条件 | 窗口 |
|---|---|
| 本轮 D0 0 次 | 未启动 |
| 第 1~3 次 **且当日板块仍在涨、扩散≥50%** | **主买区** |
| 第 1~3 次但当日转跌/扩散<50%，或第 4~5 次 | 回踩区（只挂单不追） |
| >5 次或启动已超 7 个自然日 | 只持区 |

六档输出，**主表只取「可开」**：

| 档 | 含义 |
|---|---|
| **可开** | 强势板块主买区内 |
| 降级 | 板块可跟，但时点/闸门吃紧（列原因） |
| 普涨跟涨 | 涨幅≥2% 且扩散≥70%，但**超额<1.5** ⇒ 普涨跟涨、无独立资金 |
| 闸门拦 | L1/L2/L3，列触发原因 |
| 板块未启动 | 本轮无 D0 |
| 未覆盖 | 不在 `sector_map.json`，**不进主表** |

⚠ **「未覆盖」不进主表是刻意的**。圆通速递那笔就是样本：物流方向当天零资金，
「分散」当了理由买进去，对冲变成白亏。宁可错过，也不碰不知道属于什么方向的票。

⚠ 午盘口径限制：`scr_sweep` 只在收盘跑 ⇒ 午盘「双通过」侧读的是**昨收**筹码口径，
板块层（D0/闸门/距低点）是**实时**的。报告头会分别标明两侧数据日期。

## 五、维护流程（加票 / 换机器）

```bash
# 1) 加票：直接编辑 references/sector_map.json（入仓文件，这是唯一真源）
#    每票写 6 位数字，前缀由 ash_market.split_code 判（92 开头必先于 9 判！）
# 2) 体检（必跑，抓取数失败/重复归属/样本<3/名称串行）
<PY> gates/sector_selfcalc.py --check-map
# 3) 重建锚点（板块数变了会自动重建，但收盘后主动跑一次更稳）
<PY> gates/sector_selfcalc.py --rebuild-hist
# 4) 看闸门
<PY> gates/sector_selfcalc.py --high
```

**换机器 / 换 agent**：
- `references/sector_map.json` 在 git 里 ⇒ 拉下来就有，这是功能能否复用的**唯一依赖**。
- `data/sector_high_hist.json` 被 `/data/` 忽略 ⇒ 新机器上为空，
  `load_high_hist()` 会**自动重建并打一行提示**（不静默降级），约 10~20 秒。
- 板块数对不上（缓存 23 → 表里 24）也会触发重建，否则新板块永远没有闸门。

## 六、已知局限（别当成万能）

1. 只覆盖 `sector_map.json` 里的板块与票（当前 24 板块 138 只）。**没收录 = 没判定**。
2. 概念层用自维护表，行业层没有可用源 ⇒ **全市场 5000 只没有完整板块归属**。
   补表是唯一提升覆盖的办法，别无捷径。
3. 板块等权涨幅对**单票极端值**敏感，所以判档一律看中位数；但 `state`（D0/WARM）仍用等权，
   这是为了和扩散度同口径。
4. 东财恢复后应改回「东财概念板块 + 扩散度 + 主力净流入」作主源，自维护表降为兜底与闸门锚点来源
   （因为锚点仍需要稳定的成分股清单）。
