# 赔率与买点前移

## 赔率与买点前移（环境适配，2026-09-18）

**原则不变式**：寻找最强方向 → 等待风险收窄 → 在赔率对自己有利时下注。  
突破 / 支撑低吸 / 紧凑启动，只是实现它的不同形式，**不是互相取代的信仰**。

### 什么叫「标准突破」

本 skill 口语里的标准突破 ≈ 一年/阶段新高、杯柄、高位平台、颈线/旗面被收盘确认那一类——对应脚本的 `platform_break` / `w_bottom_break` / `flag_tl_break` /（部分）`downtrend_tl_break`，以及盘中「关键位突破 / 突破预案单」。

它**没有失效**。在流畅单边里（突破→上涨→整理→再突破），确认往往比提前几个点更重要，仍应大量使用。

> **唯一交叉项：`flag_tl_break`（旗面突破）。** 旗面本身是紧凑结构，突破点既是「突破确认」也是「波动收窄后的第一次启动」——它归入哪一类，取决于**止损到结构失效位的距离**（越近越算前移），不取决于模式名。别把这条交叉当成前后矛盾。注意 `downtrend_tl_break` 不是交叉项：脚本在「已有旗形」时会明确不指派它（`test_flag_blocks_generic_dtl`）。

### 为什么要买点前移

近年更多行情是：快速上涨 → 快速释放 → **突破后高波动** → 漫长震荡。此时标准突破的尴尬是：

- 止损贴近 → 容易被正常 4%–8% 振幅洗掉（AEHR 类：突破后次日深撤仍可再新高）。
- 止损放到真正结构支撑 → 单笔风险常到 8%–10%，而预期空间只有 15%–20% → **赔率不够划算**。
- **A 股更吃亏**：T+1 不能当日纠错，为抗洗把止损放宽的成本更高。

**赛分科技案例（688758，2026-09-18，A 股 T+1 的赔率教训｜已用引擎回放核实）**

- **9/16 收盘结构**（`probe_intraday.py 688758 --asof 2026-09-16`，即 9/17 开盘前该挂的单）：`mode=w_bottom_break`、`recommend=True`，买区 **28.87–30.72**，基准日收 29.77 **已在买区内**；预案单 = **限价买 29.50**（可预挂 ✓，27.86~29.77 区间隔夜有效、不用盯盘），止损 结构 28.87 / 硬 27.86，目标 31.97，**RR 1.51:1**，数量 457 股（账户 27.0%）。
  - **9/17 实际最低 29.40 < 29.50 → 这张限价单当天必然成交。** 拿到 29.50 的成本，9/18 现价 31.80 = **+7.8%**，且距结构止损 28.87 仍有 −7.2% 缓冲。
- **9/17 收盘结构**（`--asof 2026-09-17`）：收 **31.18** 已升到买区上沿**之上** → 引擎改口「**只能挂回踩单在 30.75 一带，禁止市价追**」，并给突破预案单：**触发 站上 32.16（K=31.97 摆动前高 +0.1×ATR）/ 硬止损 31.41（K−0.3×ATR）/ 目标 35.73 / RR 4.76:1**。
- **9/18 实际**：开 31.55 → 高 **33.33** → 低 **31.16** → 现 31.80（均价 **32.31**，量比 4.97，振幅 6.96%）。回踩单 30.75 **未成交**（最低 31.16）；33.33 越过前高 31.97 后收回其下 = **收盘口径未确认**。
- **实盘 32.1 追入的代价**：①**成本比 9/16 那张能成交的 29.50 高 8.8%**；②当日最低 **31.16 已跌破预案单硬止损 31.41**，但**当日买入 T+1 卖不掉** → 止损只能推到次日、隔夜风险自担。对照：9/16 口径的持仓今天距止损还有 7% 缓冲，33.33 那波 **+6.9%** 也只有前一日持仓吃得到。
- ⚠ **为什么「RR 4.76:1」在这里是假的**：突破预案单的止损 31.41 距触发价仅 2.3%（分母窄 → R 好看），但**A 股当日买入时该止损不可执行**。这与本 skill 已有纪律一致——**只看扣成本后的账户口径，不看 R**；窄分母带来的高 R 在 T+1 下兑现不了。

→ **结论：「前移」的主要收益不是「买得更便宜」，而是「成本更低 + 止损落在可执行的当天」。** A 股尤其如此——**当日买入 = 当日不设防**。这就是"等尾盘突破成本更高，所以只能买点前移"的机制解释。

要点补充：**前移不是"提前猜突破"**，而是走引擎已给出的**可预挂限价单/`pre_breakout` 预案单**（本例 9/16 的 29.50）。但**若前一日是 `wait`（无有效买区），前一日依旧不该买**（见下方强制决策 4）。

### ★ 预判买 vs 顶着买：买突破的第一性选择（2026-09-19 实证，用户提出）

用户命题（2026-09-19 原话）：「**买突破 setup，预判突破的盈亏比更高**……我昨天买英特尔确认突破了，还是被扫出去了，但是如果在英特尔即将突破那天 9-17 日立刻追涨买入，就有浮盈可以扛住小幅度回撤。所以我以后的目标应该改为**追求盈亏比 + 小幅度止损**，而不是直接顶着买突破，**尤其是 A 股取得先手主动权更重要，因为是 T+1**。」

**结论：命题成立，且 A 股侧的差距比美股更大。** 以下是引擎逐日回放的实测（口径：结构止损用 `buy_zone.struct_stop`，T+1 盘中最低价触及即计「被扫」）。

#### 二、机制：为什么预判买赢

不是「预测得准」，而是**同一根止损线，买点更低 → 1R 更小 → 同样收益换算成 R 更大**。配对样本实测：

- **平均买入价差 = +2.45%（中位 +1.98%，+0.41×ATR）**：预判买永远买在更低的位置。
- **止损美元距离缩短**：同预算 $70.42 下，A 路平均可买 **94.6 股**、最坏敞口 **$797.8**；B 路平均 **27.0 股**、最坏敞口 **$159.1**，扣掉当日收盘浮盈垫后 **$122.1**。A 路「止损看着窄」是假象——**买在最强势当日收盘，次日一次正常回撤就触发**。
- **A 股 T+1 的放大效应**：信号日买入者**当天无法离场**，只能承受次日回抽。实测「信号日收盘落在振幅上 30%（强收盘，引擎偏好的突破）→ T+1 被扫 57%；落在下半区 → 36%」。**引擎越认可这个突破，顶着买越危险** —— 因为强收盘本身就意味着当日已涨到振幅顶部。

#### 三、执行规则（强制）

1. **突破类`mode`（platform_break / w_bottom_break / flag_tl_break / downtrend_tl_break）出信号时，首选入口永远是 `pre_breakout` 埋伏单，不是当日收盘价追入。**
2. **A 股**：T-1 收盘后（15:00 后）确认 `pre_breakout` 存在，即用券商**条件单 / 限价单**在 `trigger` 挂买；次日在 T 日触发成交。**T 日绝不能「确认后顶着收盘价买」**——T+1 无法当日纠错，被扫率 49~52%。
3. **美股**：`pre_breakout` 的 `trigger` 在现价**上方** → 致富证券无条件单，**不可预挂** → 只能盯盘；美股盘中在北京深夜 ⇒ **实际不可执行**。故美股遇到突破类信号时，**优先在池里选「买点在下方（回踩类可预挂限价单）」的标的**；当日突破只能选「不加仓」。这条与 A 股不是相反，是同一个约束。
4. **仓位折扣**：预判埋伏单按**全仓**（1R = trigger − hard_stop，风险预算照常）；**顶着买只给半仓**，且必须在 T 日收盘前完成、不隔夜追。
5. **失效条件**：T 日收盘价仍低于 `trigger`（未触发）→ 单子继续挂，但**不得改为收盘价买入**；价格跌破 `hard_stop` → 埋伏单作废（假突破）。
6. **`cushion_note` 必读**：触发成交后当日收盘多半已带浮盈垫，**这个垫子就是 T+1 低开的缓冲** —— 它是「先手权」的物理形式，也是 T+1 市场里唯一能替代「当日止损」的东西。

#### 四、与「不追高」的关系（不冲突）

`trigger` = 突破位 + 0.05×ATR，买的是**突破位本身**，不是延伸位；且 buy-stop 需真被触发才成交，假突破自动不成交。这正是「不追高」的执行形式，不是它的例外。

### 用户说「月线大杯柄」时：先证伪形态，再算量度是否已兑现（赛分 688758，2026-09-19）

用户视觉上认定的「杯柄」经常是**拼接错觉**。收到「杯柄 / 大底 / 新高突破」这类形态判断时，按固定三步走，
**顺序不能反**：

**第 1 步 — 证伪：把形态拆成不重叠的段，逐段命名。** 杯柄的辨识标志是「杯」与「柄」**连续、同级别、时间相当**。
赛分实际是**三段**：
| 段 | 价格 | 时间 | 真实性质 |
|---|---|---|---|
| ① | 29.00 → 14.21 | 3 个月 | **上市后崩盘**（IPO 估值消化/解禁），不是「杯」 |
| ② | 15.85 ~ 23.40 | **12 个月** | **长期底部盘整平台（base）** ← 主体 |
| ③ | 28.59 → 19.20 → 33.33 | 2.5 个月 | 平台突破 + 一次 **shakeout**，不是「柄」 |

→ 正确命名 = **12 个月底部平台上破（Stage 1→2 转折）**，不是 O'Neil 杯柄。

**第 2 步 — 逐条比对 O'Neil 硬指标**（赛分五条里四条不符）：
| 要求 | 赛分实际 | 判定 |
|---|---|---|
| 杯宽 7~65 周（多数 3~6 月） | 48 周 / 11.5 月 | ⚠ 偏长 |
| 杯深 12%~33%（熊市可 40%+） | **47.6%** | ⚠ 偏深 |
| 柄深 ≤ 杯深 1/3 且 ≤8~12% | 33.33→19.20 = **42%** | ⚠ 过深 |
| 柄在杯上半部 + **量能萎缩** | 7 月**放量**、不在上半部 | ⚠ 不符 |
| 突破放量 | 9/18 RVOL **1.98** | ✅ 符合 |

**第 3 步（最容易漏）— 先算「经典量度是否已兑现」，再说空间。**
```
杯柄量度 = 突破点 + 形态高度 × 1.0   →  赛分: 23.40 + 7.55 = 30.95
```
赛分现价 **32.80 已越过 30.95 达 +6.0%** ⇒ 正确答案是「**这个级别的量度已经走完**」，
剩下的不是杯柄空间，而是**平台突破后的常规趋势延伸**。
**绝不能说成「前面还有 30% 空间」** —— 把已兑现的量度当成未来空间，是这类提问最常见的错答。

**量度口径必须并列给出**（选不同的突破点/起涨点，结果差 15% 以上），并标注哪个已被越过：

| 口径 | 赛分数值 | 现价 32.80 相对 |
|---|---|---|
| 突破点 23.40 + 杯深 7.55（×1.0） | 30.95 | **已越过 +6.0%** |
| 起涨点 19.20 + 杯深 7.55 | 26.75 | 已越过 +22.6% |
| 突破点 ×1.618 延伸 | 35.62 | +8.6% |
| 平台再投射半量（31.97 + 3.78） | 35.75 | +9.0% |
| 平台再投射 ×1.0（31.97 + 7.55） | 39.52 | +20.5% |

**⚠️ 与用户趋势派纪律的接口**：用户纪律是「**突破单不设目标位、用移动止损让利润奔跑**」。
所以量度表只能作为**参考**，**措辞不能变成「到 35.77 就走」** —— 用前高/量度当目标位 = **框架错配**
（2026-09-06 已因同类错误被纠正过一次）。

**⚠️ 空间之外必须叠加的约束（不许只讲上涨空间）**：
1. **隐形减持雷**：持股跌破 5% → 后续减持**不再公告 = 不可监控抛压**（赛分 2026-09-16 一致行动人降至
   4.9999997%）。**止损是唯一防线**，不能因形态好看而放宽。
2. **止损是否落在噪声带内**：赛分 9/18 单日振幅 **2.17 元** > 距用户止损 **1.64 元**
   → **一次正常日内波动就能打掉止损**。这是买入时埋下的，**不是现在该改的** ——
   绝不能因此下移止损（手痒模式高发点），只能接受它。
3. **两档止损要分清口径**：用户自设 31.16（收盘破）vs 引擎结构止损 31.97（更紧 0.81）——
   盘前必须二选一写死，不许盘中摇摆。


所以要问的不是「形态够不够教科书」，而是三件事（研报/对话必须能回答）：

1. **在哪里知错？**（结构失效位）  
2. **错了亏多少？**（相对入场的 % / R）  
3. **对了能赚多少？**（目标1 空间 vs 上述风险）

### 两种更常优先的入场（仍只映射到现有六种，禁止自拟第七种）

标的筛选**不变**：强行业里的强票、相对强度够、有量、最好已证明「有人要」。不是改成抄弱势底。

| 表象 | 找什么 | 映射到本 skill |
|---|---|---|
| 关键支撑附近低吸 | 强势股回撤到前期突破位 / 重要均线 / 平台上沿 / 明确密集区；买的是**可定义的风险**，不是「跌够了便宜」 | 优先看 **`line_pullback`**；大阳后缩到防守带看 **`impulse_pause`** |
| 紧凑盘整后第一次启动 | 振幅与成交逐步收缩、K 线变紧、回撤变浅；供给衰减后**第一次明确启动**，不必等一年新高/所有前高被扫完 | 优先看 **`flag_tl_break`**（旗面=紧凑结构，见上）与 **`impulse_pause`**；「临近启动」的真正渠道是 **`pre_breakout` 预案单**——它**不是第七种买法**，而是与 `mode` **并存**的挂单渠道（活平台 `platform.kind=="pressing"` 或下降斜线距价 ≤1.2×ATR 时，挂 buy-stop 在突破位、不追高）。**前移的第一主渠道就是它**：SDGR 2026-09-14 活平台沿 21.40 距收盘仅 0.64×ATR，当日 `mode` 只给「大阳回踩 18.84–19.86」（从未发生），按预案单 21.45 成交 → 至今 **+29.9%** |

> 盘中的 **通道 A/B/C** 不在此表的"优先"之列：它们是分钟级通道，单笔 R 确实更小，但**本 skill 自己的回测口径下净账户仍全为负**（预案单 −0.019%/笔；通道 A −0.001%~−0.014%；通道 B −0.172%；通道 C −0.151%~−0.152%，见「盘中通道回测结论」节）。所以盘中通道**只可小仓试错、必须自带失效条件，不得当默认优先**——「别死等日线新高」不等于「换成无证据的盘中追单」。

两者底层同一句：**风险已经收窄，但行情还没有被充分交易。**  
- 支撑低吸 ≈ **空间上**风险收窄（离失效位近）。  
- 紧凑启动 ≈ **波动上**风险收窄（振幅/供给收缩后的扩张）。

### Agent 强制决策（出计划时）

1. **先算标准突破路径的赔率**：若按「等收盘站上 / 突破预案」入场，硬止损要放到何处才不会被常态波动扫掉？单笔风险是否已经接近目标1 空间的一半以上？若是 → 在对话里标「标准突破·赔率偏弱」。
2. **同时扫描前移路径**：同一只强票，是否已有可执行的 `line_pullback` / `impulse_pause` / 旗形·紧凑启动？若有且 **知错更快、单笔风险更小、到目标1 的 R 更好** → **优先写前移买点**，标准突破降为「若错过前移、仅在流畅趋势里的备选」。
3. **环境开关**（可量化口径，别用"感觉很强"）：`regime=continuation` **且**突破后 **2 个交易日内收盘脱离突破位 ≥1×ATR**、且回撤未跌破突破位 → 判为流畅主升，可主做标准突破，不必为了「提前几个点」去猜支撑；反之（突破后次日即深撤、日振幅 ≥4%、或止损被迫放宽到 ≥8% 才能抗洗）→ 转前移口径。
4. **禁止用事后结果改写规则**：例如赛分当日盘中冲新高、**收长上影（假突破）** → 不能倒推「昨天就该预判突破、在 32 下随便买」。昨天能买的前提是：**昨天已有前移类 mode + 有效买区**；若昨天是 `wait`，事后便宜 ≠ 当时纪律允许。反过来，若昨天确有有效买区而当时没买，那要复盘的也不是「该预判突破」，而是**为什么没执行既有买区**。
5. **禁止**把「我觉得会突破」写成突破模式的买区下沿之下挂单——突破类买区仍必须在突破位之上（见买区不变式）。想买突破之前，只能走支撑/盘整启动对应的 mode。
6. **本节只改呈现与推荐顺序，不改引擎输出**：`mode` / `priority` / `verdict` 仍由六种买法决定（`wait` 就是 `wait`）。前移节的作用是决定**先写哪条路径、标注哪条赔率偏弱**，以及**是否用 `pre_breakout` 预案单替代临场追单**——它不是一条能绕过六种模式的通道。

7. ★★ **每次出作战计划必须「高亮盈亏比最高的路径」（2026-09-20 用户定，强制，不可省）**

   用户原话：「**能买的低成本当然比追着买要强。后续每次输出作战计划时，高亮盈亏比最高的路径**。」

   **做法（对每只票都做，不是可选）**：
   - **枚举**该票所有「买入价 × 止损锚」组合。止损锚只能用**结构锚**（均线 / 突破日均K 实体中点 / 突破日低点 / 摆动低点 / 前低），不许自拟；买价从上到下扫（追突破价 → 平台沿 → 前低 → 均线 → 大阳回踩 1/3、1/2）。
   - **只保留可执行组合**：每股风险 **≥ 0.25×ATR**（低于此值必被毛刺打掉 = 纸面赔率，直接剔除，如「75.43 买 / 74.32 止」名义 R 5.41 实为 0.22×ATR）；且风险不得让单笔亏损越过账户风险预算。
   - **算 R**：`R = (目标 − 买入) ÷ (买入 − 止损)`。同一买点对不同目标 R 不同 → **近端墙（实测前高/长上影高点）与远端（上一个枢轴）两个都写**。
   - **呈现**：在报告与对话里用**独立高亮卡**给出 R 最大的那一条，含 **买入价 / 止损 / 每股风险 / 仓位股数 / 金额 / 风险占账户比例 / 需回落（或需上涨）幅度 / 到各目标的 R**；作战计划表的**第一行**就是它。其余档位按 R 降序排列。
   - **必须显式标注赔率差的路径**：「追突破」档若非最高 R，必须在同一行写 **「赔率偏弱·不建议」**（德邦 688035 实测：过昨高 80.49 的 R 仅 0.17，低挂 76.27 是 3.67，**同一张票差 21 倍**）。
   - **禁令**：不许只给「引擎原口径」一条路径就交差；不许把「引擎给的买区下沿」当默认推荐（它可能是止损位，也可能是错误锚，见 T0 取K口径）。

   > 配套：`probe_intraday.py` 的「预案单 + 盈亏比 + 买入上限 P_max」是引擎层口径；本节要求的是**在它之上再做一次全档枚举**，因为引擎只给一条路径，而收益全部来自「买哪一档」。
