# 顶部标志 K 线识别（top-signals）· 五形态 + 次日确认制

> **用途**：识别顶部标志 K 线并给出可执行的处置口径，供筛选层、`rule123` 与报告统一调用。
> **来源**：老罗 2026-09-25 分两批定 ——
> **第一批**：① 增加三根典型形态与变种识别（墓碑线 / 上吊线 / 射击之星，并要求「如果有需要避雷」）；
> ② 追加位置闸门「最高价是这一波行情的最高，左边没有大量 K 线高点比它高，否则不算顶部」；
> ③ 追加「配合巨量概率更大，而且需要次日确认，次日走弱 100% 是顶部了，如果反包了就推翻结论」。
> **第二批**：④「顶部十字星作为**次级**的高危信号」；⑤「巨量大阴线作为**顶级**的高危信号」。
> **实现**：`top_signals.py`（不 import `rule123`，避免循环依赖，自带迷你 ATR）。
> **单票硬指标**（同日追加）：`top_verdict()` + `python top_signal_check.py <code>` —— 跑个股时**单独打出来**的一项，退出码 `ok=0 / alert=1 / block=2`（见 §6.3）。
> **一句话结论**：**形态当日不是判据，次日走弱才是** —— 五根形态都只是「提醒你盯次日」的触发器。
> ⚠️ **第二批给出的「次级 / 顶级」分级，回测不支持**：它作为清单标签保留（用户要看得见），
> 但**不得拿来排序预测力** —— 两类形态当日都无预测力，且都走**同一条**次日确认制。详见 §0 第 4 条、§4.2。

## 0. 五条硬结论（先看这个，再看形态）

`python research/research_top_candles.py --universe sample` 可复现（Q1~Q5：`--sample-n 400` ⇒ 393 只随机全A / 169,247 根日线 / 后 5 日；
**Q6**（跳空 / 断头铡刀 / 大阴线上影 / 射击之星放宽）：同脚本 `--sample-n 1100` ⇒ **1079 只 / 465,317 根**，见 §4.3）。
**关键方法**：每组一律用**同位置对照组**（「是这一波高点但无形态」的普通 K 线），否则会拿「强势票的 beta」冒充「形态的信息量」。

1. **形态当日没有预测力** —— 相对同位置对照超额 **+0.68%、t=1.59（不显著）**。
2. **「必须是这一波最高点」这道位置闸门不成立** —— 闸门内 +0.68 vs 闸门外 **+0.48（t=3.39）**，非高点组反而超额更稳。但它仍是老罗要的定义，**保留为标注 `is_top`，不作否决依据**。
3. **「次日走弱」才是那个信号，且与形态无关** —— 有形态 −6.64% vs 无形态 −6.95%，**t=0.43** ⇒ 三根形态在「走弱」之上**一点信息都没多加**；反包组 **+1.37%** ⇒ 推翻成立。
4. **★ 第二批两形态（十字星 / 大阴线）没有改变上面任何一条**（追加后重跑验证）：
   - 两者**当日也都无预测力** —— 大阴线超额 +0.06 / t=0.11，十字星 −0.25 / t=−0.40；
   - 「次日走弱确认」之后两者都落到**对照同一量级** —— −5.91% / −8.66% vs 对照 −6.95%；
   - ⇒ **否决依据统一锚在「次日走弱」**，两个新形态**不走特殊通道**（见 §4.2）。
   - ⚠️ 一度实现过「大阴线跌幅已实现 ⇒ 当日自确认、不等次日」，**回测推翻、已撤回**：
     当日 −0.28%（对照 −0.34%）无信息，而 **80.9% 的大阴线会在其后被反包（+1.75%）**
     ⇒ 跳过确认等于把 4/5 的票误杀。
5. **★ 跳空 / 断头铡刀也都没能成为新维度**（2026-09-25 SNDK + 隆基两个案例后补测，§4.3 / §4.4）：
   - **跳空**放大的是**波动不是方向** —— 低开（−1.1%~−1.4%）与高开（−1.36%）**一样差**，
     只有「无跳空」明显更好（+0.20%）；−5% 概率 16.6% ⇒ 40%~48%。
   - **断头铡刀三个版本全部零信息**：两连阴版 +0.30%（t −0.20）／
     单根版 159,813 例超额 **−0.04**／四要件齐备版 −0.22 ⇒ **明确否定**（避雷⑬）。
   - ⚠️ **但归因找到了**（§4.4）：真正有信息的是「**前60日涨幅 ≥+60% × 跌破 MA20**」
     （同层超额 −0.4~−0.5，样本外复核通过），且**分水岭在 MA20** ——
     「失守 MA20 但没破全部四线」(−0.49) 与「破四线」(−0.41) 几乎同值
     ⇒ 「一口气破几条线」**不构成额外信息**；而前60日涨幅 <+20% 时破四线是**正的**（洗盘）。
     它属于**趋势层**的职责，**不进本模块**（本模块只认形态 K 线）。
   - ⇒ 形态族**仍是五根**，不加第六个；跳空不接 veto（避雷⑫）。
5b. **★ 「断头铡刀」与「顶部标志 K 线」是两套互不对齐的定义**（2026-09-25 五个口述案例后确认，§4.5）：
   铡刀 = **均线关系**定义（跌破 MA5/MA10/MA20/EMA10 ⇒ 趋势转折）；
   顶 K 线 = **位置 + 次日行为**定义。实测五个案例里，**唯一四要件齐备的那一根恰恰不是波峰，
   而三个真波峰四要件一个都不齐**。⇒ 「一口气破几条线」不构成顶部判据（与第 5 条的零信息互相印证）。
   同批还定下：**取消大阴线的上影门槛**（数学上 `upper_r ≤ 0.45` 恒成立，原 0.20 反而漏掉
   「冲高回落」这一最典型形态 —— 茅台 2021-02-18 就是被它卡掉的）、
   **射击之星的「下影 / 收位」暂不放宽**（放宽是「平局」，不足以拿单案例改阈值，§1 末条）。

> 注：加入第二批形态后，**对照组的构成变了**（长实体阴线与十字星从「无形态」桶里被抽走），
> 所以第 2 条的数字由上一版的「+0.70 / −0.07」更新为「+0.68 / +0.48」，**结论方向不变**。

⇒ 因此 veto 默认只在 **「波峰 + 次日走弱」** 时生效（见 §5「veto 语义」）。

**由此推出的处置口径**（`top_verdict` 的三档，见 §6.3）：
`block`（0 信息量之上确实有信息）= 避雷；`alert` = **只预警缩仓、不否决买点**；
`invalidated` = 形态已被反包作废，**回落成 `ok`，不预警**（报成预警就是把方向说反）。

## 1. 五根形态与变种

**第一批三根**是「冲高被卖回」的同族表达，**差别只在实体厚薄与影线方向**；
**第二批两根**的**方向来源与它们不同**（见下 ⚠️）。比例量一律以**根幅**为分母：

`rng = h − l`；`body_r + upper_r + lower_r ≡ 1`；`pos = (c − l) / rng`（收盘位，1 = 收在最高，0 = 收在最低）。

| 形态 | 英文/键 | 判据（阈值见 `top_signals.py` 顶部常量） | 变种 |
|---|---|---|---|
| **墓碑线** | `gravestone` | **几乎没有实体**：`body_r ≤ 0.10` + 长上影 `upper_r ≥ 0.60` + 几乎无下影 `lower_r ≤ 0.10` + 收在低位 `pos ≤ 0.25` | `doji`（`body_r ≤ 0.03`，标准墓碑十字）/ `narrow`（窄实体墓碑） |
| **射击之星** | `shooting_star` | **实体小但非零**：`0.10 < body_r ≤ 0.35` + 长上影 `upper_r ≥ 0.50` + 下影小 `lower_r ≤ 0.15` + 收在低位 `pos ≤ 0.35` | `textbook`（上影 ≥ 2×实体，教科书射击之星）/ `small_body`（小实体长上影） |
| **上吊线** | `hanging_man` | **长下影**：`lower_r ≥ 0.50` + 小实体 `body_r ≤ 0.30` + 几乎无上影 `upper_r ≤ 0.15` + 实体居上端 `pos ≥ 0.55` + 下影 ≥ 2×实体 | `dragonfly`（长下影十字，蜻蜓/T字，极端变种）/ `yin`（阴线上吊线，卖方更强）/ `yang`（阳线上吊线） |
| **顶部十字星**〔第二批〕 | `doji` | **实体 ≈0**：`body_r ≤ 0.05`（上下影不论宽窄） | `long_legged`（上下影都 ≥0.35，长脚十字）/ `upper`（上影占优）/ `lower`（下影占优） |
| **大阴线**〔第二批〕 | `big_yin` | **长实体阴线**：`tone=yin` + `body_r ≥ 0.55` + 收在低位 `pos ≤ 0.30`（**上影不设门槛**，见下 ⚠️） | `textbook`（`body_r ≥ 0.75`，几乎无影线）/ `long_body`（上影 ≤0.20 的长实体阴线）/ `spike`（**上影 >0.20 的「冲高回落」大阴线**） |

- **优先级（顺序不能动）**：墓碑线 → 射击之星 → 上吊线 → **大阴线 → 十字星**。
  十字星**必须最后** —— 墓碑线的 `doji` 变种（长上影十字）与上吊线的 `dragonfly` 变种（长下影 T 字）要先被那两根吃掉，
  剩下的才叫「十字星」；大阴线（实体 ≥0.55）与三根长影形态（实体 ≤0.35）天然互斥。
- **老罗原话对得上**：射击之星 =「比墓碑线稍微好一点，实体小，但也是长上影」—— 即墓碑线加了实体、放宽了上影下限的变种。
- ⚠️ **十字星没有「均衡」变种**：`upper_r + lower_r + body_r ≡ 1`，`body_r≈0` 时两者不可能都小，
  「上下影一样长」不是独立分支 —— 初版写过 `balanced` 分支，是**数学上不可达的死代码**，已删。
- ⚠️ **★ 大阴线的上影门槛已取消（2026-09-25，茅台案例驱动）**：
  原口径有 `upper_r ≤ 0.20`，两个问题 ——
  ① **数学上多余**：`upper_r = 1 − body_r − pos`，而 `body_r ≥ 0.55`、`pos ≥ 0` ⇒
     **`upper_r ≤ 0.45` 恒成立** ⇒ 任何 ≥0.45 的上限都不可能被触发；
  ② 原 0.20 恰好把**最典型的顶部形态「冲高回落」排除在外** ——
     茅台 2021-02-18（历史最高 2627.88 当天）实体 0.718 ✓、下影 0.037 ✓、收位 0.037 ✓、
     位置 = 波峰 ✓，**只因上影 0.245 被卡掉**，引擎当时**全程无反应**。
  大样本（波峰大阴线 1,575 例，新旧口径对照）：
  | 组 | 例数 | 已确认占比 | 确认后 | 已推翻占比 | 推翻后 |
  |---|---|---|---|---|---|
  | 旧口径 上影 ≤0.20 | 1,011 | 18.1% | −7.29% | 81.9% | +1.63% |
  | **新增 上影 >0.20** | 564 | 22.5% | −6.54% | 77.5% | +1.41% |
  | 合计（**已上线**） | 1,575 | 19.7% | −6.98% | 80.3% | +1.55% |
  ⇒ **同量级、样本 1.56×、确认率更高** ⇒ **不稀释、覆盖更完整** ⇒ 已取消，
  按上影三分变种（`textbook` / `long_body` / `spike`），**`BY_UPPER_SPIKE` 只作标签、不作门槛**。
  当日分层也一致（不限位置，后 5 日期望）：上影 ≤0.20 **+0.46%** / 0.20~0.35 **+0.62%** /
  0.35~0.45 **+0.72%** —— 上影越长当日反而越好 ⇒ 看不出任何「上影要短」的证据。
- ⚠️ **★ 射击之星的「下影 / 收位」约束暂不放宽（2026-09-25，比亚迪案例后测）**：
  比亚迪 2022-06-13（那一波的最高点 358.86）坐标「实体 0.153 / 上影 0.551 / 下影 0.296 / 收位 0.449」
  **两条都不满足**现行口径（`lower_r ≤0.15`、`pos ≤0.35`）⇒ 未命中、引擎 `ok`。
  大样本对照（波峰位置）：
  | 口径 | 候选 | 已确认占比 | 确认后 |
  |---|---|---|---|
  | 现行 下影≤0.15 / 收位≤0.35 | 1,512 | 13.4% | −6.51% |
  | 放宽 下影≤0.20 | 2,106 | 13.2% | −6.89% |
  | 放宽 下影≤0.30 | 3,086 | 13.7% | −7.12% |
  | **不限**（两者均达数学上界） | 3,249 | 13.8% | −7.13% |
  ⇒ 确认率**不塌**、确认后**略更负**（能补上比亚迪 06-13：放行后次日走弱 ⇒ 直接 `block`），
  但候选**翻 2.1 倍**（全组合 `alert`/缩仓翻倍），且差异**统计上不显著**（SE ≈ 1.5~1.7）。
  ⇒ **不因单一案例改阈值**（与 SNDK 跳空案同一纪律）；维持现状，把 2022-06-13 记为
  **已知未覆盖样本**，若要放宽须先给出「alert 翻倍 ↔ block 增量」的净收益证据。
  数学注：`lower_r` 与 `pos` 的**数学上界都是 0.40**（`1 − 0.50 − 0.10`）⇒
  「下影≤0.40 / 收位≥0.40」等于不限，现行 0.15 / 0.35 **才是真闸门**。
- ⚠️ **两批的差别不在判据，在「方向来源」**：

  | | 方向从哪来 | 确认方式 |
  |---|---|---|
  | 第一批三根 | 形态 + **位置**（形态本身不含方向） | 等**次日**走弱 |
  | 顶部十字星 | 同上（实体≈0，方向全靠位置给） | 等**次日**走弱 |
  | 大阴线 | 形态**看起来**自带方向（跌幅已实现） | **也等次日** —— 实证表明当日无信息（§0 第 4 条） |

- **信号级别标签（GRADE）**：`PATTERN_GRADE` —— 大阴线 = **顶级**、十字星 = **次级**、第一批三根 = **标准**。
  这是老罗给的清单标签（**用于显示**），**回测不支持它排序预测力**（三者当日超额都不显著）。

## 2. 四道闸门

| # | 闸门 | 函数 | 口径 |
|---|---|---|---|
| ① | **形态** | `classify_shape()` | 影线/实体比例达标（§1） |
| ② | **位置** | `is_wave_high()` | **是这一波的最高点** —— 左侧 `lookback`(=60) 根内没有更高的 K 线高点（老罗追加）。不通过的不叫「顶部标志 K 线」 |
| ③ | **量能** | `volume_ratio()` / `volume_tier()` | 巨量 `≥2.0×`20日均量 / 放量 `≥1.5` / 平量 `≥1.0` / 缩量 `<1.0` |
| ④ | **确认** | `confirm_state()` | 次日走弱 ⇒ `confirmed`；其后收盘反包 ⇒ `invalidated`；否则 `pending` |

**闸门②的返回值三态**：`ok=True`（是这一波高点）/ `ok=False`（左侧有更高高点 ⇒ 不是顶部，只进 `rejected`）/ `ok=None`（左侧不足 5 根，样本不足不判定，避雷⑨）。

**闸门④的判定顺序**（`confirm_state`，**反包压倒一切**）：

```
for 信号K线之后的每一根：
    收盘 > 信号K线最高价        ⇒ invalidated（反包/收复上影，推翻）
for 信号K线之后的每一根：
    收盘 < 信号K线收盘          ⇒ confirmed（走弱）[破全根 / 破实体 / 收低]
否则                            ⇒ pending（夹在 [信号收盘, 信号最高价] 之间）
```

## 3. ⚠️ 避雷清单（13 条 · 老罗追问「如果有需要避雷」）

| # | 雷 | 说明 |
|---|---|---|
| ① | **同名不同义（最大的雷）** | 上吊线 vs 锤子线、射击之星 vs 倒锤子线，**形态完全一样**，区分**只有位置**。同一根长下影 K 线：涨了一段之后是**顶部**，跌了一段之后是**底部反转（看涨）**。⇒ 位置闸门是命名前提，不通过的只进 `rejected`，绝不叫「顶部标志 K 线」。 |
| ② | **形态当日不是判据** | 回测 t=1.64 无预测力。它只是**触发器** —— 提醒你「这里值得盯次日」，别拿当日形态当既成顶部。 |
| ③ | **未确认 ≠ 顶部** | 信号当日只是预警，次日走弱才算数（老罗口径）。 |
| ④ | **反包即作废** | 其后收盘收复信号 K 线最高价 ⇒ 上影线的抛压已被吃掉，形态失效（该组后 5 日 **+1.37%**）。不能既看多突破又看空这根 K 线。 |
| ⑤ | **无量不算数** | 长上影若不放量，大概率只是插针/试盘。量能是**概率放大器**。 |
| ⑥ | **量能放大的是波动，不是方向** | 巨量组后 5 日最低 ≤−5% 概率 **56.3%**（缩量 38.5%）、最高 ≥+5% **54.9%**（缩量 49.5%）、标准差 11.66（缩量 11.87）⇒ 用**仓位**承担，**不用「量够不够」当准入闸门**（同项目既有口径：波动系数 ≠ 准入闸门）。 |
| ⑦ | **要看收盘位，不能只看涨跌幅** | 收盘位 `pos=(c−l)/(h−l)`。墓碑线/射击之星必须收在**低位**（`pos ≤ 0.25 / 0.35`）。**一根 +1% 的红线照样可以是墓碑线**（开在最高、收在最低、全天净卖出）。呼应 2026-09-24 国瓷材料案例：「逆势红盘 ≠ 强势」。 |
| ⑧ | **数据口径** | 涨跌停/一字/停牌复牌/除权日的影线不可比。振幅 ≤0.5% 的近一字直接跳过；振幅 >4×ATR 的异常 bar 标 `abnormal` 并**降级为预警**（该组实测 −3.12%，但成因是利空跌停/复牌，不能当形态判据）。 |
| ⑨ | **样本不足不判定** | 左侧不足 5 根**不作位置判定**（返回 `None`），不得默认「是高」。 |

## 5. veto 语义与仓位系数

**veto 默认 `confirmed`（回测支持）**：只在「波峰 + 次日走弱」时否决 `recommend`。
信号当日**不改** `recommend`，只降档预警（形态当日无预测力，t=1.64）。

**`veto="signal"`**：信号当日即否决（老罗 2026-09-25 初版选项；**回测不支持，留着备选**）。

**概率分档 `prob_tier(state, vtier, tone, pattern=None)`** —— 严格区分「方向」与「波动」：

| state | 量能 | 档位 | 含义 |
|---|---|---|---|
| `confirmed` | 巨量 | **极高** | 巨量 + 次日走弱已确认 |
| `confirmed` | 其他 | **高** | 次日走弱已确认 —— 数字**按形态引 `CONFIRM_EV`**（三根 −6.6% / 大阴线 −5.9% / 十字星 −8.7%），**不得混引** |
| `pending` | 巨量 | 中高 | 巨量但未确认 —— 放大的是波动（−5% 概率 56%） |
| `pending` | 放量·阴线 | 中高 | 放量但未确认 |
| `pending` | 放量·阳线 | 中 | 阳线版压制力弱一档 |
| `pending` | 平量 / 未知 | 中 | 仅形态 |
| `pending` | 缩量 | 低 | 缩量长影，多为插针/洗盘 |
| `invalidated` | — | 作废 | 已被反包推翻 |

- **`pattern="doji"` 的额外规则**：**未确认**时档位下压到「中」（形态当日信息量更低）；
  **已确认时不压** —— 那时方向信息来自「走弱」而非形态（§4.2【B】）。
- ⚠️ **大阴线没有特殊分支** —— 初版的 `self_down`「当日自确认」已删除（实证推翻，见 §0 第 4 条）。
- **`BLOCK_TIERS = ("极高", "高")`＝已确认档**才够格否决 `recommend`。方向（期望）**只由 `state` 决定**；量能只动**波动档**（用仓位承担），不动方向档。
- **仓位系数 `_size_factor`**（advisory，**不自动生效**）：已确认 → **0**；巨量未确认 → **0.5**；放量 → **0.75**；其余 1.0。

### 6.3 单票通道 —— 硬指标（2026-09-25 追加）

老罗原话：「这个判断顶部的逻辑**可以单独提取作为硬指标**，我在跑个股的时候，如果出现这种**要避雷**。」

⇒ `top_verdict()` 是**单票唯一结论出口**（不是第二套判定，而是把 `analyze_top_signals` 的
原始输出翻成一句「要不要动手」的话）。**三个消费方 + 一个独立 CLI 都读它**，任何一方都不得
自己再解释一遍 `plan["top_signal"]`：

| 通道 | 位置 | 表现 |
|---|---|---|
| 终端摘要 | `battle_analyze.summarize()` | 有信号才打：`★★ 顶部硬指标 [X] 顶部已确认·避雷（退出码 2）：…` |
| HTML 报告 | `report_render.build_top_signal()` | 首屏「最高盈亏比路径」下方独立卡片（左边框 block 红 / alert 橙）+ 首屏徽标 + §10 一页汇总一行 |
| probe 终端 | `probe_intraday._print_top_signal(plan)` | A 股 `probe()` / 美股 `probe_us()` 的买区行下方；并放进 `out["top_signal"]` |
| **独立 CLI** | `top_signal_check.py` | `python top_signal_check.py <code> [--us] [--strict] [--json] [-v]` |

**`level` 与 `exit_code` 同值**（多票取最大；取数失败 = 3）⇒ 可直接用于流程拦截：

```bash
python top_signal_check.py 601208 || echo "顶部硬指标命中 → 先别下单"   # block=2 / alert=1
python top_signal_check.py 601208 --json | python -c "import json,sys;print(json.load(sys.stdin)['verdict']['level'])"
```

| level | exit | 触发条件 | 处置 |
|---|---|---|---|
| `ok` | 0 | 无信号（含**已被反包推翻**） | 本项不构成限制 |
| `alert` | 1 | 出现形态但未确认（`pending`） | **只预警 + 缩仓，不否决买点**；等次日（走弱=确认，收复推翻线=作废） |
| `block` | 2 | 波峰 + 标志 K 线 + **次日走弱** | 硬避雷：`rule123` 已置 `recommend=False`；持仓按结构止损减仓/离场，空仓禁止买入 |

**五根形态一视同仁**（墓碑 / 上吊 / 射击之星 / 十字星 / 大阴线）—— 上面三档对它们完全一样，
**不存在「顶级形态可以跳过次日确认」这种通道**（依据见 §0 第 4 条）。
`grade`（`顶级` / `标准` / `次级`）**只用于显示**，不影响 `level`，但会出现在 `advice` 文案里
（如 `硬避雷［顶级高危］：…`、`预警［次级高危］…`）。

`--strict` ＝ `veto="signal"`（形态当日即 `block`，老罗初版口径；**回测不支持，默认关**）。
`--holding` / `--flat` 只改 `advice` 文案（持仓腿 / 空仓腿），**不影响 level 判定**。

`top_verdict` 返回的关键字段：`level / level_cn / level_ascii / exit_code / hit / veto / strict /
live_last / date / pattern_cn / variant_cn / o,h,l,c / body_r,upper_r,lower_r,pos / is_top /
state / state_cn / prob / vol_cn / rvol / confirmed_date / confirmed_level / confirm_reason /
invalidation / size_factor / reason / advice / n_signals / n_rejected / signals / rejected /
pitfalls / signal / top`。

## 7. 对外接口（API）

| 函数 | 作用 |
|---|---|
| `classify_shape(bar)` | 纯形态识别，返回 `dict(pattern, variant, variant_cn, tone, metrics)` 或 `None` |
| `pattern_grade(pattern)` / `PATTERN_GRADE` | 信号级别标签：**顶级**（大阴线）/ **标准**（第一批三根）/ **次级**（十字星）—— **仅用于显示**，不作判据 |
| `is_wave_high(bars, i, ...)` | 位置闸门，返回 `dict(ok, left_max, span, bars_since_higher, gap_pct)` |
| `volume_ratio(bars, i, n=20)` / `volume_tier(rvol)` | 量比代理 / 分档 |
| `confirm_state(bars, i, m, max_age=None)` | 次日确认制，返回 `(state, detail)` |
| `analyze_top_signals(bars, ...)` | 主入口（rule123 / 扫描器内部用） |
| **`top_verdict(bars, ...)`** | ★ **单票硬指标唯一出口**（CLI / `battle_analyze` / `report_render` / `probe` 共用，见 §6.3） |
| `top_fractal` / `top_fractals` | 顶分型（含失效校验）—— 收敛旧脚本的重复实现 |
| `screen_exclude(bars, ...)` | 筛选层统一口径 |
| `format_signal(sig, brief=True)` | 单条信号渲染成一行中文 |

`analyze_top_signals(veto="confirmed", live_last=False, ...)` 返回：
`ok / signals / rejected / detections / best / block / block_reason / state / pattern_cn / invalidation / rvol / size_factor / summary / pitfalls / atr14`。

**`live_last=True` 的语义**：末根是**未走完的当日 K 线**，此时「次日确认」只能看到前一根为止的收盘证据，半日 bar 的收盘价不足以判「走弱」（可能是盘中插针），故**不纳入确认扫描**（只看 `bars[:-1]`）—— 否则盘中一探底就会误报「顶部确认」。

## 8. 顶分型口径收敛（7 处 → 1 处）

本仓库原有 **7 个筛选脚本各自实现了一遍顶分型**（含失效校验），改一处必漏六处。现全部收敛到 `top_signals.top_fractal(s)`：

| 脚本 | 原函数 | 收敛后 |
|---|---|---|
| `screen_mlcc_2026-09-24.py` | `top_fractal` | `hits[0][1] if hits else None`（保留「窗口内最早那根」） |
| `screen_kc50_2026-09-25.py` | `tf_valid` | `(True, hits[0][1]) if hits else (False, None)` |
| `screen_semi_2026-09-25.py` | `top_fractal_valid` | 同上 |
| `screen_storage_2026-09-25.py` | `tf_valid` | 同上 |
| `screen_device_2026-09-24.py` | `top_fractals` | `([d for (_i,d,_h,_l) in hits], broken)` |
| `screen_refine_2026-09-24.py` | `top_fractals` | 同上 |
| `check_tf_601208.py` | `top_fractals` | `[(d, h) for (_i,d,h,_l) in hits]` |

**失效校验口径**：顶分型 = 中间 K 的 `high`、`low` 均为相邻三根中最高；其后出现更高高点 ⇒ 已破坏，不算（否则会误杀，见东富龙 2026-09-15）。`top_fractals` 返回 `(hits, broken)`，`hits` 元素为 `(i, d, h, l)`。
